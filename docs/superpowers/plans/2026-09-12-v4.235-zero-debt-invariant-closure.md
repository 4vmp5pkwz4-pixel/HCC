# v4.235 Zero-Debt / Invariant Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove every in-browser boot self-test failure without weakening an invariant, then harden continuous scale transitions, scene/frame ownership, Cycles/Universe authority sharing, and release verification.

**Architecture:** Treat scientific state as authoritative and rendering as a projection: `world -> frame -> scale -> camera limits -> visible instruments`. Diagnose each boot failure against the last known 0-failure revision before changing implementation. Add independent regression checks for every defect class, then make scale/frame transitions and the Cycles universe consume shared scientific authorities rather than parallel decorative state.

**Tech Stack:** Single-file Three.js/WebXR atlas (`index.html`), Node.js verification scripts, Playwright browser harness, GitHub Actions.

**Spec:** User-approved “Invariant-first closure / Zero-Debt” design from 2026-09-12.

## Global Constraints

- Do not weaken, delete, skip, or inflate a tolerance merely to make a failing assertion green.
- Preserve one-authority discipline: scientific values are computed once; views consume them.
- Rendering/premium/GPU degradation may change presentation quality only, never scientific values or solver resolution.
- Preserve existing scientific firewalls, uncertainty labels, source provenance, and refusal semantics.
- Require zero boot failures, zero page errors, green source/API/verifier checks, passing scale round trips, and declared-frame scene ownership before release.
- Preserve mobile safe areas, reduced-motion behavior, light/dark mode, Premium on/off, and WebXR contracts.
